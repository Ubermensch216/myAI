# 이미지 생성 — 설치·운영·사용 가이드 (쉬운 설명)

이 문서는 이미지 생성 기능을 **설치하는 관리자**, **운영하는 관리자**, **사용하는 직원** 세 관점에서 쉬운 말로 설명합니다.
기술 상세(환경변수 전체, API 스펙, 티어 표 등)는 [IMAGE_GENERATION.md](IMAGE_GENERATION.md)를 참고하세요.

---

## 전체 그림 먼저 (비유)

이미지 생성은 **3개 부품**이 협력하는 구조입니다.

| 부품 | 역할 | 비유 |
|---|---|---|
| **브라우저** (개인 PC) | 사용자가 글로 요청, 그림 받아봄 | 주문서 쓰는 손님 |
| **Node 서버** (:3000) | 요청 받아 줄 세우고 중계 | 주방에 주문 넘기는 홀 직원 |
| **이미지 워커** (:7861, 파이썬+GPU) | 실제로 그림을 그림 | 요리하는 주방 |

핵심: **그림 그리는 주방(워커)은 별도 프로세스**입니다. 그래서 그림 그리다 GPU가 터져도 채팅(텍스트)은 멀쩡합니다.
셋 다 **부서 GPU 워크스테이션 1대**에 같이 돌고, 개인 PC는 브라우저만 씁니다.

폐쇄망(인터넷 차단)에서 어려운 점은 **단 하나** — 인터넷에서 받아야 하는 것(파이썬 패키지, AI 모델 파일)을
**미리 받아 USB/외장디스크로 옮겨야** 한다는 것뿐입니다.

---

## 1. 설치 (관리자, 최초 1회만)

인터넷 되는 PC에서 재료를 모으고 → 폐쇄망 PC로 옮겨 설치하는 **2단계**입니다.

### 준비물
- **스테이징 PC**: 인터넷 되는 아무 PC (재료 다운로드용)
- **운영 PC**: 폐쇄망 GPU 워크스테이션 (실제 사용처)
  - dev(개발/테스트): RTX 5060 Laptop, 8 GB급
  - ops(실운영): RTX PRO 5000 Blackwell, 48 GB급
- USB나 외장 디스크 (재료 옮기는 용)

### A단계 — 스테이징 PC (인터넷 됨)

인터넷으로 받아야 할 **두 가지**를 한 번에 모읍니다: ①파이썬 패키지(휠), ②AI 모델 파일.

스크립트 한 줄로 끝납니다:
```powershell
.\scripts\stage-image-worker-wheels.ps1 -CudaIndex cu128 `
  -Models @("stabilityai/sdxl-turbo","black-forest-labs/FLUX.1-schnell") `
  -HfToken <허깅페이스토큰>
```

이게 하는 일:
1. **PyTorch(cu128)** + 나머지 패키지를 `offline-bundle\wheels\`에 다운로드.
   - ⚠️ `cu128` = CUDA 12.8용. RTX 50 시리즈(Blackwell)는 **반드시 이 버전**. 구버전 받으면 GPU 인식 못 함.
2. **AI 모델**을 `offline-bundle\models\`에 다운로드.
   - SDXL-Turbo: 누구나 받음.
   - FLUX.1-schnell: **사전에 허깅페이스 사이트에서 라이선스 동의 + 토큰 발급** 필요(gated 모델). 동의 안 하면 다운로드 거부됨.
3. **SHA256SUMS.txt** 생성 — 파일 무결성 체크용 지문.

→ `offline-bundle\` 폴더 통째로 USB에 복사.

### B단계 — 운영 PC (인터넷 안 됨)

USB에서 `offline-bundle\`을 옮긴 뒤:

**① 무결성 확인** (옮기다 깨졌는지 검증) — `SHA256SUMS.txt`의 지문과 실제 파일 대조. MISMATCH 뜨면 다시 복사.

**② 파이썬 패키지 설치** (인터넷 대신 USB 폴더에서)
```powershell
cd services\image-worker
python -m venv .venv ; .\.venv\Scripts\Activate.ps1
pip install --no-index --find-links <번들>\wheels torch torchvision torchaudio
pip install --no-index --find-links <번들>\wheels -r requirements.txt
```
`--no-index` = "인터넷 보지 말고 이 폴더에서만 찾아라"는 뜻.

**③ 모델 파일 배치** — `offline-bundle\models\`의 모델 폴더를 운영 PC의 정해진 위치(예: `C:\AI\models\sdxl-turbo`)로 복사.

설치 끝. 이건 최초 1회만.

## 2. 운영 (관리자, 일상)

### 기동 (서버 켜기)

워커는 **GPU에 맞는 런처 스크립트**로 켭니다. 환경별 설정(모델/해상도/타임아웃)이 스크립트에 박혀 있어 골라 쓰기만 하면 됩니다.

```powershell
# 개발용 RTX 5060 (SDXL-Turbo, 768px)
.\scripts\start-image-worker.rtx5060.ps1 -Offline -ModelPath C:\AI\models\sdxl-turbo -Warmup

# 실운영 RTX PRO 5000 (FLUX, 1024px)
.\scripts\start-image-worker.rtx5000pro.ps1 -Offline -ModelPath C:\AI\models\flux-schnell -Warmup
```

옵션 뜻:
- **`-Offline`**: 폐쇄망 모드. 인터넷 조회 끄고 로컬 모델만 씀. 모델 경로가 잘못됐으면 **켜는 즉시 명확한 에러로 멈춤**.
- **`-ModelPath`**: 모델 폴더 위치. 폐쇄망에선 필수.
- **`-Warmup`**: 켤 때 모델을 미리 메모리에 올림. **이게 핵심** — 안 켜면 첫 사용자가 모델 로딩(수십 초~분)을 다 기다리다 타임아웃 납니다. 켜면 첫 요청부터 빠름.

그다음 Node 서버 기동: `npm start`.

### 상태 점검 (잘 돌아가나 확인)

```
GET http://127.0.0.1:7861/health
```
- `loaded: true` → 모델 메모리에 올라옴(준비됨)
- `tier`, `model`, `device: cuda` → 어떤 등급/모델/GPU 쓰는지

브라우저 화면에서는 **이미지 생성 토글 버튼이 보이면** 워커 정상(서버가 워커 살아있는지 자동 확인 후 버튼 노출/숨김).

### 자동으로 관리되는 것들 (손 안 대도 됨)

| 항목 | 동작 |
|---|---|
| **그림 파일 정리** | `data/generated-assets/`에 저장, **24시간 뒤 자동 삭제**(1시간마다 청소). 디스크 안 참. |
| **재시작 견딤** | 일일 한도·작업 상태가 디스크에 저장됨. **서버 재시작해도** 한도 안 풀리고(우회 불가), 끝난 그림은 계속 조회됨. 진행 중이던 건 "재시작으로 중단" 표시. |
| **GPU 메모리 보호** | 한 번에 1장씩만 생성(줄 세우기). VRAM 부족하면 해상도 자동으로 낮춰 재시도. |
| **큰 GPU 속도 최적화** | RTX PRO 5000 같은 큰 카드는 모델을 GPU에 통째로 올려 빠르게(`auto`), 작은 카드는 메모리 아끼는 모드. 자동 판단. |

### 운영자가 조절하는 값 (`.env`)

| 설정 | 의미 | 권장 |
|---|---|---|
| `IMAGE_MODEL_TIER` | GPU 등급(모델/해상도 결정) | dev=`mid`, ops=`max` |
| `IMAGE_GEN_TIMEOUT_MS` | 생성 제한시간 | 240000~300000 (4~5분) |
| `IMAGE_WORKER_WARMUP` | 시작 시 모델 예열 | **`1` 강력 권장** |
| `IMAGE_DAILY_LIMIT_PER_USER` | 1일 생성 한도 | 50 (그룹·등급별 버킷) |
| `IMAGE_RETENTION_HOURS` | 그림 보관 시간 | 24 |
| `IMAGE_CUDA_OFFLOAD` | GPU 메모리 모드 | `auto` |

### 장애 대응 (자주 나는 것)

| 증상 | 원인 | 조치 |
|---|---|---|
| "Image generation timed out" | 모델 cold start / 타임아웃 짧음 | `-Warmup` 켜기, 타임아웃 상향 |
| 토글 버튼 안 보임 | 워커 꺼짐/미응답 | 워커 기동 확인, `/health` 점검 |
| 켜자마자 에러로 멈춤 | 폐쇄망인데 모델 경로 틀림 | `-ModelPath` 경로 확인 |
| GPU 인식 못 함 | torch 버전 틀림(cu121 등) | cu128로 재설치 |
| 일일 한도 초과 메시지 | 정상 (한도 도달) | `IMAGE_DAILY_LIMIT_PER_USER` 조정 |

## 3. 사용자 관점 (직원, 별도 설치 없음)

개인 PC는 **브라우저만** 있으면 됩니다. 설치 전혀 없음.

### 쓰는 순서
1. **`정보탐색` 대화방**에 들어감.
2. 입력창 옆 **이미지 생성 토글 버튼** 누름 (워커가 살아있을 때만 보임).
   - 켜지면 입력창 안내문이 "생성할 이미지를 설명하세요…"로 바뀜.
3. (선택) 작은 패널에서 **스타일**(보고서/카드뉴스/아이콘/사진/일러스트), **비율**(1:1, 4:3, 16:9, 3:4), **장수** 고름.
4. 만들 그림을 **한국어로 설명** 입력.
   - 예: `상수도 누수 점검 절차 카드뉴스 일러스트`
5. 전송 → "이미지를 생성하는 중입니다…" 표시되며 대기 (보통 수 초~1분).
6. 완료되면 **그림이 대화 카드로** 나타남. 마음에 안 들면 **"다시 생성"** 버튼으로 재시도.

### 알아둘 점
- 그림은 **24시간 뒤 서버에서 삭제**됩니다. 필요하면 받아두세요.
- **1일 생성 한도**가 있습니다(기본 50건). 초과하면 안내 메시지.
- 부적절한 내용(노골적/공문서 위조 등)은 **자동 거부**됩니다.
- 생성 그림엔 **"AI 생성" 표시(메타데이터)**가 박힙니다.
- 입력한 프롬프트 **텍스트는 로그에 안 남습니다**(개인정보 보호). 생성 횟수 같은 메타데이터만 기록.

---

## 한 줄 요약

- **설치**: 인터넷 PC에서 스크립트로 패키지+모델 모아 USB로 옮겨, 폐쇄망 PC에서 `--no-index`로 설치 (최초 1회).
- **운영**: GPU별 런처를 `-Offline -ModelPath -Warmup`으로 기동. 정리·재시작·메모리는 자동 관리.
- **사용자**: `정보탐색`에서 토글 켜고 한국어로 설명만 입력. 설치 불필요.
