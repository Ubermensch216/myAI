# NotebookLM-Style Source Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a NotebookLM-style loop where assistant answers can become room-level sources, while keeping AI-generated material visibly secondary and not promoting it to department notebooks.

**Architecture:** Reuse the existing assistant message action surface, `/api/export` file generation, `room.documents` material flow, encrypted IndexedDB persistence, and `/api/chat` document context path. Generated sources are stored client-side as document-like room materials with provenance and trust metadata; binary export data is generated by the server on demand and stored only when within a small configured cap.

**Tech Stack:** Plain browser ES modules, Express, existing `server/exportFiles.js`, encrypted IndexedDB app state, current chat/document context pipeline.

---

## Feasibility Review

The PRD is feasible as a phased feature. Phase 1 fits the current architecture because uploaded documents already live in `room.documents`, are persisted in browser IndexedDB, rendered in the material panel, and are sent back to `/api/chat` as context. Assistant messages already have copy/download/Studio actions, and answer export already supports `md`, `pdf`, `docx`, and `hwpx`.

The PRD should not be implemented as one large change. Source-loop MVP, Studio editor UX, Source Guide, Output Library, and notebook promotion are separate subsystems. Implementing them together would raise regression risk in chat, persistence, export, and Studio.

Main corrections before implementation:

- The PRD text contains mojibake in user-facing Korean labels. Restore labels before coding, for example `자료로 추가`, `AI 생성`, `검증 필요`, `문서 편집`, `원문 보기`.
- Do not store generated files server-side in MVP. Keep room-generated sources in encrypted browser state only.
- Avoid storing large PDF/DOCX/HWPX base64 blobs by default. Store `text`, metadata, format, and optional `dataBase64` only under a small size cap.
- Treat generated sources as secondary context in prompts. They must not become independent proof for legal or factual claims.
- Defer department notebook promotion. It requires admin review, provenance, and access-control design.
